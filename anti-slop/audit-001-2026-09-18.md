# BYTE interface audit 001

Date: 2026-09-18

Scope: typography, visual hierarchy, responsive behavior, motion, accessibility, and content readiness. This audit does not modify the website.

## Direction read

The existing direction is an industrial studio stage: near-black space, warm paper, acid-yellow illumination, physical pendant lamps, and a restrained editorial/brutalist type system. The concept is specific and worth preserving.

Inferred dials: ENERGY 3 / RHYTHM 3 / MOTION 3.

## Findings

1. **HIGH - Secondary text fails contrast on the dark surface (R-25).** `--dim` (`#6f6d63`) against `--ink` (`#0a0a09`) measures 3.81:1, below the 4.5:1 requirement for the many 10-14px labels, bios, links, roles, and navigation items that use it. Raise the dark-theme secondary-text token while keeping a separate, quieter decorative token for non-text rules.

2. **HIGH - Several interactive controls lack a guaranteed, high-contrast focus treatment (R-32).** The hero scroll button, lamp controls, stage navigation buttons, copy/mail controls, member email link, and footer links do not share an explicit `focus-visible` style; the custom `div[role="button"]` lamp is particularly dependent on browser defaults. Add one global focus system that remains visible against both ink and paper.

3. **HIGH - Reduced-motion support is incomplete (R-32, R-35).** `MotionConfig` covers Framer Motion, but Lenis smooth scrolling, the continuously animated dust canvas, CSS bounce indicators, and inline stage transitions continue under `prefers-reduced-motion`. Disable or simplify all four so the page has a genuinely calm mode.

4. **HIGH - Placeholder content is presented inside an otherwise finished experience (R-38).** Every member bio says "Add a proper bio here," and the README identifies the bios, skills, and addresses as placeholders, but the interface does not label the site as a draft. Replace these with approved team content before treating the page as final.

5. **MEDIUM - The typography system has character but not enough discipline (R-06).** Unbounded, Space Grotesk, and JetBrains Mono suit the industrial identity, yet the implementation relies on many isolated sizes, tracking values, and breakpoint-specific clamps. Define a small named type scale and role-based styles so headings, labels, body copy, and metadata feel related rather than individually tuned.

6. **MEDIUM - Small mono type is overused for information that must be read (R-06).** Navigation, roles, tools, skills, addresses, and footer copy repeatedly use 10-12px mono with wide tracking; this turns supporting information into visual texture. Reserve mono for terse operational labels and raise contact details, roles, and descriptive metadata into the body face at a readable size.

7. **MEDIUM - Uppercase display language flattens the hierarchy (R-06).** Nearly every section label, headline, capability, process step, and control speaks in uppercase. Keep uppercase for the strongest stage cues, but introduce sentence/title case in secondary headings and actions so importance is communicated by more than size alone.

8. **MEDIUM - Motion is consistently cinematic but too persistent (R-19).** Scroll translations, opacity reveals, sticky sections, a 440-500 viewport-height stage, bounce loops, flicker, dust, and hover movement all compete for attention. Preserve the lamp reveal as the signature motion and quiet the navigation and supporting-section effects.

9. **LOW - Section sizing makes the narrative feel longer than its content (R-05).** Multiple `min-h-dvh` sections plus the 440/500vh team runway and 165vh contact sequence create a slow, theatrical scroll even where the copy is brief. Tighten the informational sections so the extended pacing belongs mainly to the team reveal.

10. **LOW - Component boundaries are too faint in low-light UI states (R-20).** `--line` (`#2a2924`) against `--ink` measures only 1.36:1, leaving email controls, skill chips, dividers, and the stage footer hard to distinguish. Introduce separate subtle-divider and interactive-boundary tokens; interactive boundaries should reach 3:1 or be made clear by another persistent cue.

11. **LOW - The contact-card hover creates a weak icon treatment (R-20).** Cards switch to paper while the mail icon stays acid; acid against paper has very little contrast and visually disappears. Swap the icon to ink (or another dark token) in the light hover state.

12. **LOW - Major visual decisions are documented unevenly (R-31).** The README explains the acid accent and stage concept, but it does not record why each typeface has its role, why the fixed dark theme is appropriate, or why the supporting motion exists. Add a short design-direction document before the next implementation pass so future edits preserve the intended identity.

## What already works

- The lamp-stage concept is distinctive and content-specific rather than a generic portfolio template.
- The palette is controlled: ink, paper, neutral greys, and one meaningful acid accent.
- Section compositions vary and follow a coherent studio narrative.
- Navigation destinations and visible controls have real behaviors by code inspection.
- Mobile layouts include deliberate reflow, compact navigation, safe-area padding, and 44px primary targets.
- The production build and ESLint both pass on 2026-09-18.

## Verification limits

The site was verified by source inspection, contrast calculation, `npm run build`, and `npm run lint`. A browser click-through and viewport screenshot review were not available in this audit, so R-35 remains incomplete until the approved fixes are exercised interactively at mobile, tablet, and desktop widths.
